## 背景与目标

用户是个人小红书图文创作者。过去依赖「看平台流行什么」的热搜榜，但热搜榜无法真正支撑选题；更有效的做法是围绕自己关心的主题，主动检索、聚合、深挖出高价值内容，作为图文创作的素材与依据。

本产品（自媒体运营工作台）最终目标是覆盖“主题深挖 → 图文生成 → 账号接入 → 一键发布”全链路。第一版只交付「主题收集 + 挖掘」：用户输入主题关键词，系统检索小红书相关内容、构建内容簇、挖掘高价值内容，最终产出一份主题深度报告。图文生成与发布明确放到第二版。

成功的样子：用户输入一个主题关键词，得到一份该主题的深度报告——包含围绕该主题的内容簇概览、高价值内容清单与挖掘结论，可直接作为选题和创作依据。

判断指标（可观察）：
- 输入主题关键词并启动后，能检索到该主题下的相关内容（非空，或检索不到时给出明确空状态）。
- 产出深度报告，报告包含内容簇概览、高价值内容清单、挖掘结论。

## 目标用户与场景

- 目标用户：个人小红书图文创作者（当前即用户本人，单用户使用）。
- 场景：开始创作前，围绕一个选定主题，快速收集平台上的相关高价值内容，确定选题方向与素材。

## 数据来源

- 数据源：用户自有小红书账号 + 开源 xiaohongshu-mcp 的关键词检索（`search_feeds`）与内容详情（`get_feed_detail`）。
- 登录：QR 码登录 + cookie 持久化，不存账密明文。
- 合规：沿用用户此前“暂缓合规、先跑通流程”的语境；对外使用或上线前须另行做合规与账号安全评估。

## 非目标

- 图文生成（选题 → 文案 → 配图）
- 发布（一键发布）
- 热搜榜（方向作废）
- 小红书以外的平台
- 账号接入功能（登录仅作为数据抓取的依赖，不等同于账号接入/管理）
- 用户未提出的：定时监控、通知提醒、数据导出、多用户与登录体系

## 未决问题

- 「高价值内容」的判定标准？推荐：按互动数据（点赞 + 收藏 + 评论）加权排序，取前列 N 条。
- 深度报告包含哪些内容/字段？推荐：内容簇概览 + 高价值内容清单 + 挖掘结论（摘要）。
- 并行多主题是否第一版做？推荐：第一版先单主题跑通，多主题并行放 P1 或第二版。
- 每个主题检索/聚合的内容规模上限？推荐：默认 top 30–50 条，后续可配置。
- 单个主题是否支持多关键词组合？推荐：先单关键词起步。
- 内容条目的展示字段最小集？推荐：标题、作者、互动数据（点赞/收藏/评论）、发布时间、原文链接。
